# SWP — Smartwatch Protocol (v1)

Reference implementation: `shared/protocol/` (C++17, used by both firmwares).
TypeScript port: `web/src/protocol/` (tested byte-for-byte against fixtures generated by
the C++ code, `tests/host/gen_fixtures.cpp`).

## GATT

| UUID | Name | Properties | Security |
|------|------|------------|----------|
| `7a1e0001-5c3b-4f8e-9d2a-6b1e5a7c0de0` | SWP service | primary | — |
| `7a1e0002-…` | RX (client → device) | write, write-without-response | encrypted + MITM |
| `7a1e0003-…` | TX (device → client) | notify, read | encrypted + MITM (CCCD too) |
| `7a1e0004-…` | Info | read | open: `DeviceInfo` payload only |

The companion (Bluedroid) and the watch's web-config peripheral (NimBLE) expose the same
service. The watch is the central towards the companion.

## Framing

Frames are a byte stream split into ATT-sized pieces by the transport:

```
A5 5A | ver(1) | type(1) | seq(u16 LE) | len(u16 LE, ≤4096) | payload | CRC-16/CCITT-FALSE(u16 LE, over ver..payload)
```

The decoder resynchronises on the magic bytes after corruption; frames with another major
version are dropped. All integers are explicit little-endian; strings are UTF-8 with a u8
(or u16) length prefix and are truncated on code-point boundaries. Decoders validate every
length and list count and reject truncated payloads. New fields may only be **appended**
within a major version; decoders ignore unknown trailing bytes.

## Session

1. Client writes `Hello{proto, min_proto, role, capabilities, firmware, name}`.
2. Device answers `HelloAck` (same layout). Any other message before `Hello` → `Error`.
3. Watch↔companion: both send `Heartbeat` every 20 s; the watch drops and reconnects the
   link after 75 s of silence. Heartbeat bit 0 = companion is streaming A2DP (watch avoids
   bulk requests; companion also throttles transfers itself).

## Bulk transfers

`TransferBegin{id, kind, total, crc32, chunk, start_offset, meta}` → receiver replies
`TransferAck{next_offset, window, status}`. The sender keeps at most `window` chunks beyond
the acknowledged offset (credit-based backpressure). The receiver accepts only the chunk at
`next_offset` (go-back-N): a gap produces `status=Rewind`. Completion is acknowledged only
after the CRC-32 matches (`status=Done`). An interrupted transfer is resumed by requesting
the object again with `resume_offset`; the receiver keeps its prefix if size, CRC and meta
match. Map tiles use `kind=MapTile`, `meta = z(u8) x(u32) y(u32)`.

## Pairing and trust

* Companion: display-only static passkey. TODO(PROTOTYPE): fixed to `616616`
  (`CONFIG_COMPANION_PROTOTYPE_PASSKEY`), so anyone nearby during the pairing window can
  bond; production must use a per-device random passkey. New bonds are only accepted
  during the pairing window (5 min after boot, or 2 min after pressing BOOT).
* Watch peripheral (web config): advertises only when enabled in Settings (5 min); shows a
  random passkey or a numeric-comparison code on screen.
* Both reject links that are not LE Secure Connections + MITM. A static web page therefore
  cannot configure a device without the passkey (for the prototype companion that passkey
  is public, so the pairing window is the only gate).
